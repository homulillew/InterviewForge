## 补充串讲一：Attention 为什么与这三个项目都有关系

**面试官：** “你一直提长上下文和训练显存，先把 attention 讲清楚。”

**参考回答：** Scaled dot-product attention 的基本形式是 `softmax(QKᵀ/√d_k + mask)V`。Q 与 K 决定当前位置对已有位置的权重，V 提供聚合内容；因果 mask 限制未来信息可见性。缩放用于控制点积随维度增长的量级，避免 softmax 过早饱和。[Transformer 原论文](https://arxiv.org/abs/1706.03762)

回到项目：长搜索轨迹和检索上下文都扩大模型需要处理的序列，增加计算与缓存压力。上下文选择既是信息保留问题，也是资源问题；不能把“窗口装得下”当成“模型能可靠使用全部信息”。

**继续追问：** “信用 mask 也是加到 QK 上吗？”——不是。信用 mask 决定哪些策略输出位置承担相应学习信号，attention mask 决定可见信息，两者可以同时存在而语义不同。

## 补充串讲二：MHA、MQA、GQA 与 KV cache

**面试官：** “为什么估计缓存时要用 KV heads，而不是只看 query heads？”

**参考回答：** MHA 通常让不同头具有各自的 K/V；MQA 共享一组 K/V；GQA 让多个 query heads 按组共享 K/V。因此 query heads 相同的模型也可能有不同 KV cache 规模。[GQA 原论文](https://arxiv.org/abs/2305.13245)

粗略容量可以按 `2 × 层数 × KV头数 × head维度 × 总缓存Token数 × 每元素字节数` 估算，2 表示 K 和 V。真实实现还存在分页、对齐、共享和元数据开销，不能把该算式当精确峰值。

回到 P04：G=4 与长回答增加需要缓存的 Token；回到 P03：把大量重复证据塞入上下文也会消耗容量。先减少无用信息，再评估并发与资源配置。

## 补充串讲三：四种“mask”不要混用

| 名称 | 控制对象 | 项目中的例子 |
|---|---|---|
| Attention/causal mask | 一个位置能看到哪些上下文 | 防止读取未来 Token |
| Padding mask | 哪些位置只是补齐 | 不让 padding 污染注意力或损失统计 |
| Response/label mask | 哪些生成位置承担监督或策略目标 | 排除 prompt、工具观察等位置 |
| Credit mask | 已允许策略位置中，哪些得到特定信用 | P02 结构回溯选中的动作 |

**关键接法：** “某位置没有直接 loss”并不意味着该输入没有影响后续表示，也不意味着共享参数更新不会改变该位置概率。P02 还要检查正向优势之外是否存在其他损失项。

## 补充串讲四：学习信号可以从三个层次被改变

| 层次 | 干预 | 本次项目 |
|---|---|---|
| 问题/组层面 | 改变哪些组进入训练 | P04 正确性混合组筛选 |
| 轨迹/动作层面 | 改变哪些策略位置接受信用 | P02 结构动作掩码 |
| 优化目标层面 | 改变比率、裁剪和归一化 | GRPO/GSPO 的实际 loss |

**面试官：** “三种都用是不是最好？”

**参考回答：** 它们可以组合，但也会叠加选择偏差和成本。需要固定基础条件，分层比较接受分布、mask 密度和目标差异，再检验交互；不能将各自独立增益直接相加。P04 mixed 组不是唯一有梯度的组，P02 最终引用也不是全部有价值的探索。

## 补充串讲五：用户价值不等于代理指标

**面试官：** “三个项目都报了漂亮指标，为什么还不够？”

**参考回答：** Pass@1、Recall、正确性对比密度与平均评分分别观察结果、检索、训练信号和评审反馈。它们都可能被预算、题集构成或代理偏差影响。需要把指标接回实际任务质量、失败后果和总成本，再说改进是否值得保留。

- P02：工具调用减少要检查困难题与探索能力。
- P03：Recall 增加要检查最终证据是否完整且被正确使用。
- P04：mixed 密度提高要计入被拒绝样本的生成成本；win/tie 要拆开胜、平、负。
