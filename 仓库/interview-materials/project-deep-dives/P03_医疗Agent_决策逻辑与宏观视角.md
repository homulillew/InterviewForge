## 决策链：Q41–Q44

### Q41｜你怎么证明需要 Multi-Agent，而不是一个强模型加检索？

**锚点：** C1 · **类型：** 决策 · **概念：** 必要性 · **问法模式：** DEC。

**参考回答：**

先在相同模型能力、证据与预算下比较，观察复杂任务是否确实需要不同职责独立处理。如果单模型已经达到质量要求，额外协作只增加延迟和错误传递，就不值得默认启用。
我把多 Agent 用在可分解、可检查且收益明确的子任务组合上，而不是为了展示架构。比较还应控制总 Token，避免把更多计算当作协作本身的优势。

**追问与接法：** 改选条件：任务简单、角色输出高度重复或协调成本占主导时，使用单路径。

### Q42｜风险、质量与成本冲突时，Router 先优化什么？

**锚点：** C1 · **类型：** 决策 · **概念：** 路由目标 · **问法模式：** DEC、EVAL。

**参考回答：**

先明确不能违反的风险与权限约束，再在满足任务质量的范围内优化成本。不能用一个任意加权分数把高影响错误和节省 Token 相互抵消。
高风险也不等于无条件更多 Agent，应选择能够解决实际问题的处理路径。阈值需要用误判代价与开发集校准，评估时分层报告。

**追问与接法：** 改选条件：业务用途变化后可以重定目标，但不能看完测试结果才修改权重。

### Q43｜为什么保留确定性分诊，而不是让大模型统一理解？

**锚点：** C1 · **类型：** 决策 · **概念：** 规则维护 · **问法模式：** DEC。

**参考回答：**

明确的应急和权限边界需要稳定可审计，交给单次模型输出会增加不必要的不确定性。模型负责复杂语境，程序负责已确定的策略执行。
规则代价是维护与误触发，所以需要否定、主体和教育性场景回归，而不是无限增加关键词。规则和模型应互补，不能互相成为免责理由。

**追问与接法：** 改选条件：语义变化频繁且规则无法可靠表达的部分，可交给模型判断，但执行边界仍要明确。

### Q44｜Planner 为什么不允许任意任务数量和角色？

**锚点：** C1 · **类型：** 决策 · **概念：** DAG 自由度 · **问法模式：** DEC、DAG。

**参考回答：**

更多任务会增加预算、协调和失效组合，也让计划更难核验。我使用有界结构，把自主性放在任务目标和依赖安排上，而不让模型随意扩大系统能力。
边界也可能限制复杂任务，需要用失败案例判断是否真的需要扩展。放宽上限应伴随执行预算和验证能力提升，而不是只修改一个数字。

**追问与接法：** 改选条件：持续存在合法且高价值的复杂任务受限时，评估分阶段计划而不是一次无限拆分。


## 决策链：Q45–Q48

### Q45｜哪些子任务适合并行，哪些必须等待？

**锚点：** C1 · **类型：** 决策 · **概念：** 串行与并行 · **问法模式：** DEC。

**参考回答：**

独立证据检索或不同角度分析可以并行；需要消费前序结果的综合与核验必须等待。还要考虑共享资源和数据修改，即使图上无依赖也不代表执行无冲突。
我会先划清输入输出，再观察关键路径。为了减少延迟而让下游在缺失输入时猜测，会把性能优化转成质量问题。

**追问与接法：** 八股追问：如何识别最值得优化节点？结合 DAG 最长路径与实际排队，而不是只看单节点耗时最大。

### Q46｜多 Agent 失败后回退 Single-Agent，会不会重复工作又更不可靠？

**锚点：** C1 · **类型：** 决策 · **概念：** 失败降级 · **问法模式：** DEC、FAIL。

**参考回答：**

会，所以降级必须复用仍有效的证据与已完成分析，并明确哪些依赖缺失。回退是收缩执行复杂度，不是忽略原任务的风险与证据要求。
要比较降级后的质量、延迟与重试成本，避免主流程失败后再完整跑一次昂贵流程。若必要证据始终不可得，应缩小回答范围而不是继续猜测。

**追问与接法：** 改选条件：失败原因是共享模型或证据缺失时，单纯换成 Single-Agent 未必有帮助，应直接处理根因。

### Q47｜为什么不是继续优化 Dense，而要加 BM25L？

**锚点：** C2 · **类型：** 决策 · **概念：** 混合召回 · **问法模式：** DEC、RETR。

**参考回答：**

当失败集中于精确术语、缩写和实体匹配，词项检索提供了不同的补充信号；若主要是语义模型不适应领域，也应比较 embedding 改善的收益。
我会用 Dense-only、BM25L-only、融合与重排逐层消融，观察哪类查询得益。多加一路会增加维护与噪声，必须证明互补而不是只看到平均 Recall 上涨。

**追问与接法：** 改选条件：稀疏路由很少补到有效证据、却显著增加成本时，减少其范围或移除。

### Q48｜为什么用 RRF，不直接学一个融合模型？

**锚点：** C2 · **类型：** 决策 · **概念：** 融合选择 · **问法模式：** DEC、RRF。

**参考回答：**

RRF 不要求原始分数校准，实现简单、可解释，适合标签有限的起点。学习融合需要稳定标注与训练分布，可能获得更细权重，也可能过拟合题集。
我先用简单方法建立可信基线，再判断分数信息的损失是否真的限制效果。是否升级应由独立评估和维护成本决定。

**追问与接法：** 改选条件：有足够代表性标签且 learned fusion 在留出集稳定改善时，再考虑更复杂方案。


## 决策链：Q49–Q52

### Q49｜Reranker 很贵，你先减少候选还是换模型？

**锚点：** C2 · **类型：** 决策 · **概念：** 重排预算 · **问法模式：** DEC、RERANK。

**参考回答：**

先确认候选池里必要证据的位置分布。如果关键材料常在尾部，直接减候选会损害覆盖；若大量重复候选占成本，先去重和优化召回更合适。
再比较较轻重排、分层过滤和候选预算，观察最终质量而非单独重排延迟。换模型后分数与截断策略也要重新验证。

**追问与接法：** 改选条件：预算紧且证据已高度集中，可减少候选；覆盖不足时优先修召回。

### Q50｜为什么不一开始就做很复杂的语义切块？

**锚点：** C2 · **类型：** 决策 · **概念：** 语义切块 · **问法模式：** DEC、RETR。

**参考回答：**

复杂切块会增加预处理成本和可复现难度，未必改善实际查询。我先保留文档自然结构与来源位置，建立简单基线，再根据条件丢失、表格破碎等失败扩展。
切块服务检索与生成，不应独立追求语义边界漂亮。需要固定后续预算，检查是否减少误召回并保留足够支持条件。

**追问与接法：** 改选条件：规则切块持续破坏关键结构且有稳定证据时，再投入更复杂解析。

### Q51｜用户说过的信息都值得记住吗？

**锚点：** C3 · **类型：** 决策 · **概念：** 记忆准入 · **问法模式：** DEC、MEM。

**参考回答：**

不。长期保存需要明确用途、用户控制、主体与来源，短暂讨论、猜测和他人情况不应自动变成稳定画像。记忆会影响未来回答，因此写入比临时理解需要更严格。
我优先保留能够改善未来任务的明确背景，并支持更正、撤回与删除。更多记忆既增加隐私负担，也可能让过时信息干扰当前问题。

**追问与接法：** 改选条件：一次性任务或用户关闭更新时，保持会话内处理即可。

### Q52｜当前输入与已确认画像冲突，直接用最新一条覆盖吗？

**锚点：** C3 · **类型：** 决策 · **概念：** 画像冲突 · **问法模式：** DEC、MEM。

**参考回答：**

先区分明确更正、临时情境和主体变化。最新消息不一定在修改长期事实，不能只按时间排序覆盖。已确认内容与自动抽取冲突时，应遵循明确的更新策略。
当前任务可以基于用户最新明确说明处理，同时把长期写回单独审查。这样避免为了当下回答顺畅而悄悄改掉跨会话背景。

**追问与接法：** 改选条件：用户明确修改或撤回某项事实时，提供可追溯更新，而不是让旧画像永久优先。


## 决策链：Q53–Q56

### Q53｜Grounding 与 Safety 哪个更值得投入？

**锚点：** C3 · **类型：** 决策 · **概念：** 验证资源 · **问法模式：** DEC、GROUND。

**参考回答：**

看主要失败来自证据失真还是输出越界。它们处理不同问题，不能用更多 Safety 提示补救错误引用，也不能因来源可靠就跳过输出边界。
我会先建立分层错误切片，优先修影响大且原因清楚的链路，同时保留最低必要保障。投入排序由实际失败与代价决定，而不是选择听起来更重要的模块。

**追问与接法：** 改选条件：同一层误拒过多时，校准标准和输入，不简单增加检查次数。

### Q54｜质量涨了 0.1 分但延迟翻倍，你保留吗？

**锚点：** C4 · **类型：** 决策 · **概念：** 评测取舍 · **问法模式：** DEC、EVAL。

**参考回答：**

先看评分变化落在哪些维度以及是否稳定。如果改善集中在关键证据错误，可能值得；若只是更长、更礼貌，用户代价可能超过收益。
我会比较任务切片和质量—延迟曲线，必要时仅在复杂或高影响任务启用。0.1 分和翻倍都是题设，不能脱离评分量表与用户时限做统一决定。

**追问与接法：** 改选条件：没有独立质量收益或用户无法接受等待时，保留更轻路径。

### Q55｜一百个 Bad case，你先修哪一个？

**锚点：** C4 · **类型：** 决策 · **概念：** 修复优先级 · **问法模式：** DEC、FAIL。

**参考回答：**

我按错误后果、出现频率、影响范围与可定位程度排序，优先处理跨任务的根因，例如身份隔离或证据截断，而不只挑最容易修的表面问题。
修复前明确预期作用与负对照，修复后看同机制泛化及误伤。高影响低频问题也可能优先，不能仅按数量排序。

**追问与接法：** 改选条件：根因不明时先补观测和最小复现，避免直接堆 Prompt 特判。

### Q56｜LangGraph、LangChain 与业务代码的边界怎样划？

**锚点：** C1 · **类型：** 决策 · **概念：** 框架与领域 · **问法模式：** DEC。

**参考回答：**

通用框架承载模型接入、执行和状态流转，领域层定义风险、角色、证据与授权语义。换框架时，这些关键规则不应散落在提示词和回调里难以迁移。
我会复用通用能力，但核对重试、取消、检查点和状态合并的实际语义，不能默认框架名称等于已经具备所有保证。

**追问与接法：** 改选条件：框架使关键领域约束难以表达时，先建立清晰适配边界，再决定替换范围。


## 决策链：Q57–Q60

### Q57｜是否应该接入外部实时检索，弥补本地资料覆盖？

**锚点：** C2 · **类型：** 决策 · **概念：** 本地与外部检索 · **问法模式：** DEC。

**参考回答：**

要看时效需求和本地覆盖。外部检索可以补新资料，但引入来源质量、权限、延迟和可复现性问题，不能直接把网页相关性当成专业支持。
若扩展，我会保留来源分级、版本与证据校验，明确外部材料怎样进入当前请求。当前链路与拟议接入分开报告，不把设计当作已上线能力。

**追问与接法：** 改选条件：任务主要依赖稳定受控资料时，本地优先；明确需要新近信息时再增加受控外部路径。

### Q58｜用户说“不要查资料，直接回答”，系统如何选择？

**锚点：** C1 · **类型：** 决策 · **概念：** 用户反馈 · **问法模式：** DEC。

**参考回答：**

用户偏好影响速度和表达，但不能自动解除必要的风险与证据要求。先识别这是否是低风险概念解释，还是需要来源支持的具体判断，再决定可以缩减什么。
如果原任务要求与预算或偏好冲突，应明确缩小回答范围。不能保持同样强的结论却悄悄省掉支撑。

**追问与接法：** 改选条件：普通解释可采用轻路径；涉及关键比较和高影响结论时保留必要核验。

### Q59｜怎么证明是动态路由降低 Token，而不是题集更简单？

**锚点：** C4 · **类型：** 决策 · **概念：** 消融可信度 · **问法模式：** DEC、CTX、EVAL。

**参考回答：**

同题配对比较，固定模型、材料与解码条件，并按风险和复杂度分层。除了总成本，还要记录实际 Single/Multi 路径与错误路由比例。
若样本构成变化，只能比较经过明确调整后的结果，不能把两批平均数直接归因给 Router。还应设置固定单路径和固定多路径基线。

**追问与接法：** 改选条件：成本优势依赖牺牲复杂题质量时，重新校准路由或限制适用范围。

### Q60｜什么结果会让你缩减系统组件？

**锚点：** C4 · **类型：** 决策 · **概念：** 停止复杂化 · **问法模式：** DEC。

**参考回答：**

如果某组件没有改善其负责的失败类型，反而增加延迟、误拒和维护，我会优先简化。尤其多个角色输出高度重复、反馈无法执行时，增加调用不等于增加可靠性。
缩减也要做回归，确认删除后关键保障仍在。组件应有明确职责与可验证收益，不因已经投入很多成本就永久保留。

**追问与接法：** 改选条件：模型升级后某些补丁不再必要，重新寻找更简单的有效配置。


## 宏观链：Q61–Q64

### Q61｜这个系统的核心价值是医学知识更多，还是执行更可靠？

**锚点：** C1 · **类型：** 宏观 · **概念：** 医疗 Agent 的系统定位 · **问法模式：** MAC。

**参考回答：**

本项目重点是组织风险分流、证据检索和受控协作，使回答过程可追溯、可降级、可评估。知识覆盖当然重要，但架构本身不能制造临床权威。
因此我会分别评价材料质量、模型能力与运行约束，不用工程完整度代替实际场景验证。它首先是一个循证问答与 Agent 工程系统。

**追问与接法：** 继续追问：多 Agent 是否意味着专家会诊？不能这样等同，角色分工并不赋予真实专业资质。

### Q62｜什么决策交给模型，什么必须交给程序？

**锚点：** C1 · **类型：** 宏观 · **概念：** 自主性边界 · **问法模式：** MAC。

**参考回答：**

语义理解、受限计划和文本综合适合模型；身份授权、任务上限、依赖合法性、工具权限与确定性状态转换由程序执行。两者通过结构化接口连接。
程序也不能证明所有语义正确，所以输出仍需证据和任务评价。边界的依据是可验证性与错误后果，而不是“模型聪明所以都交给它”。

**追问与接法：** 继续追问：规则写不完怎么办？用分层能力与受控降级承认覆盖边界，不放弃执行约束。

### Q63｜用户为什么关心你的路由和 DAG？

**锚点：** C4 · **类型：** 宏观 · **概念：** 用户价值 · **问法模式：** MAC、DAG。

**参考回答：**

用户通常不关心组件名，关心能否得到有依据、及时且适合任务的回答。路由和 DAG 的价值应体现为复杂问题处理更完整、简单问题更省成本，以及失败时不混乱。
我会用实际任务结果和核查负担解释价值，而不是展示流程图数量。若机制没有改善这些指标，就应重新评价它的必要性。

**追问与接法：** 继续追问：用户满意就够吗？满意可能受语气影响，还需检查事实支持与风险切片。

### Q64｜为什么检索系统很好，仍不能保证可信问答？

**锚点：** C2 · **类型：** 宏观 · **概念：** 检索与可信度 · **问法模式：** MAC。

**参考回答：**

检索只提供候选信息，后续还可能误读、错误合并、丢失条件或引用不匹配。来源本身也有适用范围与时效。
可信度需要从资料准入、召回排序、上下文组织到主张支持连续检查。Recall 和相关性是必要诊断维度，不能独自代表答案正确。

**追问与接法：** 继续追问：最高优先级是什么？先修会改变关键结论的链路，再优化平均指标。


## 宏观链：Q65–Q68

### Q65｜长期记忆为什么是产品决策，而不仅是技术优化？

**锚点：** C3 · **类型：** 宏观 · **概念：** 长期记忆的产品责任 · **问法模式：** MAC、MEM。

**参考回答：**

它会改变未来回答，也涉及用户是否愿意保存、能否查看更正删除以及何时不应使用。单纯提高检索命中率不足以决定写入范围。
因此记忆准入、来源、有效期与撤回应由明确产品语义约束。用户背景和专业证据分开，避免个性化演变成未经验证的推断积累。

**追问与接法：** 继续追问：记忆越多体验越好？过时和无关信息可能增加错误与负担，需要治理。

### Q66｜这个项目的总评分应该由哪些层次组成？

**锚点：** C4 · **类型：** 宏观 · **概念：** 评测体系 · **问法模式：** MAC、EVAL。

**参考回答：**

分开看任务完成、检索覆盖、主张支持、路由与安全、记忆正确性、执行可靠性及成本。可以为特定用途形成摘要，但保留分维度结果。
高影响失败不适合被大量简单题的高分平均掉。评审应有明确标准和独立切片，模型评分也要经过案例校准。

**追问与接法：** 继续追问：平均 4.12 能支持上线吗？单个平均值不足，需要看用途对应的质量与风险证据。

### Q67｜从个人项目到多人服务，最大的变化是什么？

**锚点：** C1 · **类型：** 宏观 · **概念：** 团队化与多租户 · **问法模式：** MAC。

**参考回答：**

不只是并发数量增加，还包括用户与数据隔离、任务所有权、资源配额、取消恢复以及共享知识更新。个人运行中默认可信的操作，需要转化为服务边界。
数据库、向量库、缓存和后台任务都要传递授权范围，不能只在 HTTP 入口验证一次。先建立清楚的责任边界，再扩大吞吐。

**追问与接法：** 继续追问：容器隔离够吗？它不能代替应用层对象授权与资料访问策略。

### Q68｜你能承诺系统永不出错吗？

**锚点：** C1 · **类型：** 宏观 · **概念：** 可靠性承诺 · **问法模式：** MAC。

**参考回答：**

不能用这种绝对承诺，但可以定义具体可验证的行为：预算受控、路径可见、已提交任务可恢复、引用可解析、失败不会静默变成成功。
语义质量则用明确用途下的评估和边界说明来支撑。可靠性是多个可检验保证的组合，不能由“有安全模块”一句话覆盖。

**追问与接法：** 继续追问：怎样表达服务目标？按任务和风险定义时限、失败处理与质量要求，不把所有请求混成一个数字。


## 宏观链：Q69–Q72

### Q69｜什么叫高性价比的医疗问答系统？

**锚点：** C2 · **类型：** 宏观 · **概念：** 成本与质量 · **问法模式：** MAC、EVAL。

**参考回答：**

应比较完成一个合格任务的总成本，包含模型、检索、重排、重试和用户核查负担。低 Token 若伴随更多误判与人工返工，未必更划算。
不同场景需要不同质量门槛，因此应看分层成本曲线。优化目标是减少无效工作，而不是用低质量短答换漂亮成本。

**追问与接法：** 继续追问：延迟和成本总是一致吗？并行可能降延迟却增资源，必须分别测量。

### Q70｜你怎样说明这不是把现成框架拼起来？

**锚点：** C4 · **类型：** 宏观 · **概念：** 工程与研究贡献 · **问法模式：** MAC。

**参考回答：**

重点讲清楚风险与复杂度如何分离、DAG 的合法边界、证据身份如何跨阶段保持、以及 Bad-case 怎样被定位成通用修复。贡献在于这些决策及其可验证后果。
框架复用是正常工程方法，但不能用框架名字代替自己的设计证据。用失败前后链路和受控结果说明改进更有说服力。

**追问与接法：** 继续追问：哪些代码亲自负责？按真实职责说明，不用项目存在推断个人独立完成比例。

### Q71｜更强模型出现后，这套系统哪些部分可能被简化？

**锚点：** C1 · **类型：** 宏观 · **概念：** 模型升级 · **问法模式：** MAC。

**参考回答：**

细碎角色拆分、格式修复和重复评审可能随着能力提升而缩减；授权、来源治理、状态与任务责任不会自动消失。
我会用相同任务重评质量与成本，允许更强单模型替代某些协作路径。坚持用户目标，不坚持组件永久存在。

**追问与接法：** 继续追问：如何避免架构锁死？把领域规则与模型接口分离，并保留可替换的执行与评估边界。

### Q72｜这个项目的经验怎样迁移到非医疗 Agent？

**锚点：** C1 · **类型：** 宏观 · **概念：** 跨项目迁移 · **问法模式：** MAC。

**参考回答：**

可迁移的是按风险分配自主性、结构化计划校验、证据身份贯通、受治理的记忆与链路评估。领域特有的风险语义、资料等级和输出要求必须重新定义。
迁移时先问新任务的失败代价和真实副作用，再确定权限、状态与验收，而不是直接复制医疗角色。

**追问与接法：** 收尾：复用的是设计方法和基础设施，业务判断需要重新建立。

## 进阶演练：决策与宏观回答

每道决策题按目标与错误代价、真实备选方案、当前选择、接受的代价、改选条件展开；每道宏观题先给结论，再回到一个项目机制，最后说明可迁移与不可外推的部分。

| 面试官改变条件 | 回答必须调整什么 |
|---|---|
| 预算明显收紧 | 优先减少无效工作，必要时调整范围；不要静默改质量或主实验预算 |
| 简单基线已经满足目标 | 重新证明复杂机制的增量；允许收缩组件 |
| 关键切片退化但平均数改善 | 按实际任务重要性判断，不用平均值掩盖高影响错误 |
| 新模型消除了旧瓶颈 | 在同协议下重新比较，保留领域与验证边界，删除无效补丁 |
| 结果与假设相反 | 定位实现、测量与方法问题，保存负结果，不补造原因或数据 |

**高压分支 1：** “去掉你的核心模块也一样好，怎么办？”参考回答：先控制预算和关键配置，检查同难度切片；若确实没有稳定增量，就缩小适用范围或移除。维护目标而不是维护组件存在。

**高压分支 2：** “你讲了很多设计，究竟哪一个有实验支持？”参考回答：将已有实现、简历结果、当前可核验运行和进一步方案分开，具体指向配置、样例与比较；实验计划不能当作已完成结果，静态代码不能证明指标和个人贡献比例。
